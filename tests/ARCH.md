# Architecture: tests

VERIFIED: The suite exercises real memory and native Storage adapters, real kernel locks and Node's real Web Lock manager. Corruption tests write actual truncated or damaged byte images. Mocked I/O was rejected because the defects that matter here, such as partial reads, torn slots and lock lifetimes, live inside the real subsystems a mock would replace.

| File | Failure classes covered |
| --- | --- |
| `mvcc.test.ts` | Tree results against an independent Map; atomic batches, snapshots, conflicts, phantoms, limits and real quota failures |
| `v2-recovery.test.ts` | Torn data and head slots, committed corruption, publication boundaries and recovery from an interrupted create |
| `native-v2.test.ts` | Independent native backends with real kernel locks and real permission failures |
| `commit-groups.test.ts` | Per-key transaction conflicts (disjoint keys, changed and deleted read keys, point-read phantoms, write skew), commit groups with per-member revisions, checks and receipts in one publication, and cancelled or over-quota members that leave the rest committed; full groups for four concurrent transaction writers and a long-held snapshot that does not hold back other commits |
| `page.test.ts` | The index-page writer against `encodeFrame` in trusted mode: identical bytes for 2000 generated leaf and branch pages in both child key orders, and identical results for other names, value types and oversized pages |
| `kept-files.test.ts` | Kept head and generation files: two backends with different limits commit in turn on one database, one collects the generation the other kept open, closing the last handle releases the files to a plain Storage open, read-only files still open for reading and reject writes with `PERMISSION_DENIED`, and `syncReadBytes` reads match thread-pool reads and reject a negative bound |
| `native-performance.test.ts` | Descriptor bounds and cleanup through `/proc` on Linux and `lsof` on macOS, stale speculative roots after another client compacts, point-read corruption after cache warmup, partial read/write chunking, large binary values, scan snapshots and close draining |
| `batches.test.ts` | Batch scans on memory and native storage against the row scan for every range and limit, batch and byte budgets, stable snapshots across compaction, owned output, invalid options and row sizes, an oversized row after earlier batches, a failing frame inside a run decoded in one call, cancellation, a close from inside `sizeOf`, and the decoder budget on frames served from the read window |
| `contracts.test.ts` | API contracts no other file reached: transaction scans that merge staged writes with the snapshot under ranges and limits, the whole-database fallback past `maxTransactionOperations` distinct reads, TypeError and RangeError for invalid keys, bounds, operations, revisions, modes and budgets, zero cache budgets, early scan breaks, `close()` draining work and closing owned snapshots, the memory and native lock protocol, checksummed heads of another format version or with inconsistent fields, and a denied native read that works again once access is restored |
| `shared-reads.test.ts` | Read-only opens of one file that overlap on memory storage, through the Web Lock coordinator and on native storage, writers and removals that wait for open readers instead of failing `BUSY`, and parallel snapshot scans beside commits, compaction and collection |
| `parallel-scans.test.ts` | `split()` ranges against the full scan for 1 to 10,000 parts after overwrites and deletes, and within key intervals, on memory and native storage: order, shared boundaries, exact counts and balance; `beginRead({ at })` from a second handle or an independent native backend after writes and compaction, its pin against collection, `CONFLICT` once collected, and invalid or too-new heads |
| `scan-workers.test.ts` | The native backend's scan pool in real worker threads against a backend without one: rows, DSON types and cycles, order, key intervals, limits and batch sizes; scans below the threshold or with `sizeOf` stay in the calling thread; `LIMIT_EXCEEDED` from a worker; closing a paused snapshot or breaking early releases the workers' pins, so collection reclaims the generation; a pool whose workers cannot start returns no scan |
| `format3.test.ts` | Formats 3 to 5 on memory and native storage, the recovery tests on formats 4 and 5: a head slot restored to an older state is rebuilt from commit records on open, values above the reopening handle's `maxRecordBytes` do not stop recovery, a torn last record ends recovery at the commit before it, another handle adopts commits left without a head slot before its own, a write rejected before that adoption stays uncommitted when its group is checked again, a stored value shaped like a record stays a value; a format 3 database keeps format 3, its records and DSON object pages, and a format 2 database format 2, through commits and compaction |
| `format4.test.ts` | Compact pages on memory and native storage, in formats 4 and 5: hard keys (empty, Latin-1 and wider units, surrogate pairs cut by a shared prefix, lone surrogates, 4096 units) stay exact through batches, deletes, compaction and reopening; compact pages under a format 3 head are `CORRUPT`; random pages round-trip; malformed pages (kind, count, shared prefix, key length, truncation, trailing bytes, oversized numbers) are `CORRUPT` |
| `format5.test.ts` | Format 5 on memory and native storage: logged commits match a Map across checkpoints by page budget, snapshots, compaction and reopening; handles replay each other's commits and an older snapshot head; a damaged change list is `CORRUPT`; a commit past 16 MiB of log is a checkpoint; scan workers replay the log of their snapshot; change lists round-trip and reject disorder and truncation |
| `older.ts` | Helpers: an empty database rewritten to an older format's head, and a restored head file |
| `compaction-copy.test.ts` | Compaction's frame copy on memory and native storage: values written far from their key order, frames larger than one read run and rewritten keys survive with their revisions; a damaged frame header fails with CORRUPT |
| `frames.test.ts` | Caller-encoded frames through `batchFrames` and `putFrame` on memory and native storage: the same receipts, values and generation bytes as `batch` for typed and cyclic values, decoded values on every read path, staged frames in transaction reads and scans, insert-only conflicts with their index writes, copies at admission (also of a Node `Buffer` and of a view into a larger buffer), `TypeError` for malformed, truncated, damaged or extended frames and `RangeError` at the record, depth and length budgets with nothing committed, transaction and pending budgets, `ifRevision`, cancellation, concurrent writers on two handles, a failed head publication that the next writer adopts; `frame()` handles that commit like their values on any handle and in transactions, hold the value as it was at the call, refuse look-alikes, clones and prototypes with `TypeError` and meet the receiving handle's record budget |
| `web-locks.test.ts` | Shared pins, try-locks, cancelled waits and pinned-generation retention through `createBrowserBackend` |

VERIFIED: Correctness tests have no speed threshold, because timing assertions fail on loaded machines without indicating a defect; `make bench` measures speed separately. Native directories are temporary and removed after each run, and no test reads user data.

[Consumer tests](consumers/ARCH.md) run against the tarball installed in a separate directory. [Browser tests](browser/ARCH.md) run its bundled imports in real dedicated workers.
